# Discord Rich Presence

The Windows desktop app can optionally show local Codex, Claude Code and Pi/OMP activity in Discord. Open **Settings → Discord → Discord Rich Presence** and turn it on. It is off by default and uses the Discord desktop client; Discord's activity-sharing setting must also permit the status to be displayed. The status remains visible while the app is running, including an idle label when there is no recent session.

The activity may share the service, recorded model, effort, speed, session start time and local token totals. Codex effort and service tier come from session settings; **Fast requested** is the requested tier, not a guarantee of server-side processing speed. Claude's speed comes from the latest response's `usage.speed`; unavailable or unknown values are omitted. `S` is the selected session; `D`, `W` and `M` are this day, the Monday-starting week and this calendar month in the configured usage bucket time zone. These are local history totals, not account-wide totals or provider quota percentages. Claude totals include cache reads and writes; Codex input already includes cached input. By default, Discord proxies the user-approved animated Maomao pet image from the fork. That default is a fixed snapshot and does not automatically follow later Codex pet changes; a custom image can be chosen as described below. The local RPC protocol also includes the application ID, process ID and a request nonce. Project names, paths, prompts, transcripts, account details and usage limits are not sent. Token totals are read only while cost tracking is enabled; model and start time use a bounded read of the selected session. Usage history is refreshed at most every five minutes; incomplete or unavailable totals are omitted rather than displayed as zero. Session start means elapsed time since the recorded session began, not active working time.

The feature scans only this PC, independently of remote session settings and Mobile Connect. It excludes its own child processes and the known Claude usage-probe session. For a longer Codex turn, it also checks bounded local task-start, completion and abort markers and requires a plausible live Codex process. The process-to-session match remains approximate: after a crash, an unfinished record can be displayed as active for up to four hours, and completed sessions can still appear active briefly. Detection is bounded to 64 stale candidates, the last 512 KiB of each transcript and four hours. Older chats can also be discovered through the read-only local Codex index when indexed within the last two days; missing or incompatible indexes fall back to normal directory discovery. Unsupported or unusual installations and very long or verbose turns may not be detected. When several providers are active, the most recently updated eligible session is shown; at idle, the last observed provider is retained during this app run. Without a recent provider, one available history is shown by service; when both are available the generic monitoring status shows combined Codex and Claude totals. Disabling the setting or exiting the app closes the local Discord connection. Discord may prioritize another application's activity.

The **View on GitHub** button defaults to this fork's public repository; a custom `https://github.com/` URL can be entered in Discord settings. The button can also be turned off. The settings preview can open the selected link locally. Discord shows Rich Presence buttons to other users, but does not show them on your own profile; see the [Discord Rich Presence documentation](https://github.com/discord/discord-api-docs/blob/main/developers/discord-social-sdk/development-guides/setting-rich-presence.mdx).

The Discord application ID is `[REMOVED]` and belongs to this fork's Discord application. Discord must be running locally; the app retries when it becomes available. No bot token, OAuth login or extra process is required.

## Appearance settings

The Discord settings page includes an example preview for Codex, Claude and idle. Select the most recent session or prefer either provider; an eligible session from another provider is used if the preferred provider has none. Detailed, compact, model-first and service-focused layouts, model, effort/speed, elapsed time, session and calendar token totals, emoji, and the GitHub button can be controlled independently. Token data still requires cost tracking and available local history. The preview uses sample values; actual activity depends on detected sessions and Discord's display.

Paste a Codex Pets share link (`https://codex-pets.net/share/<id>` or `https://codex-pets.net/#/pets/<id>`) to use its public poster, or enter a public HTTPS image URL such as a GIF. The app queries the fixed Codex Pets API for the poster and does not upload local files. The site's poster is static; its sprite atlas is not itself an animated image, and the site's GIF export is generated locally rather than hosted. Leave the URL empty to use the included animated pet. Discord must be able to retrieve custom images; GIF playback depends on the Discord client. The selected URL is stored locally, excluded from portable preferences, and shared with Discord as part of the activity. Only use URLs you are willing to share.

## Validation

The local Windows test run passed 34 agent-session tests, four activity-mapping tests, four desktop IPC/settings tests, all 1,359 frontend tests, the frontend build and locale check. A live Discord desktop IPC handshake accepted the supplied application ID, activity and icon URL, and acknowledged a clear request. This is protocol evidence; it does not establish visual display or end-to-end detection of every Claude installation.

The user reported that the animated WebP appeared static in Discord. A six-frame GIF with the same timing was prepared and its published bytes and IPC acceptance were verified. Discord's image proxy returned HTTP 403 to an automated request, but after installing the GIF-backed build the real Discord desktop profile was observed over multiple frames: the pet visibly blinked and returned to its open-eyed pose. This confirms playback in that local client, not every Discord client or accessibility configuration.

# Discord Rich Presence

The Windows desktop app can optionally show local Codex, Claude Code and Pi/OMP activity in Discord. Open **Settings → Menu → Discord Rich Presence** and turn it on. It is off by default and uses the Discord desktop client; Discord's activity-sharing setting must also permit the status to be displayed. The status remains visible while the app is running, including an idle label when there is no recent session.

The activity may share the service, recorded model, effort, speed, session start time and local token totals. Codex effort and service tier come from session settings; **Fast requested** is the requested tier, not a guarantee of server-side processing speed. Claude's speed comes from the latest response's `usage.speed`; unavailable or unknown values are omitted. `S` is the selected session; `D`, `W` and `M` are this day, the Monday-starting week and this calendar month in the configured usage bucket time zone. These are local history totals, not account-wide totals or provider quota percentages. Claude totals include cache reads and writes; Codex input already includes cached input. Discord proxies the user's approved public animated Maomao pet image from the fork. The image is a fixed snapshot and does not automatically follow later Codex pet changes. The local RPC protocol also includes the application ID, process ID and a request nonce. Project names, paths, prompts, transcripts, account details and usage limits are not sent. Token totals are read only while cost tracking is enabled; model and start time use a bounded read of the selected session. Usage history is refreshed at most every five minutes; incomplete or unavailable totals are omitted rather than displayed as zero. Session start means elapsed time since the recorded session began, not active working time.

The feature scans only this PC, independently of remote session settings and Mobile Connect. It excludes its own child processes and the known Claude usage-probe session. It uses recent session-file timestamps as an approximation, so a completed session may continue to appear active for a few minutes, and unsupported or unusual installations may not be detected. When several providers are active, the most recently updated eligible session is shown; at idle, the last observed provider is retained during this app run. Without a recent provider, one available history is shown by service; when both are available the generic monitoring status shows combined Codex and Claude totals. Disabling the setting or exiting the app closes the local Discord connection. Discord may prioritize another application's activity.

The **View on GitHub** button opens this fork's public repository. Discord controls where activity buttons appear and whether they are visible on your own profile.

The Discord application ID is `1564892477213638746` and belongs to this fork's Discord application. Discord must be running locally; the app retries when it becomes available. No bot token, OAuth login or extra process is required.

## Validation

The local Windows test run passed 34 agent-session tests, four activity-mapping tests, four desktop IPC/settings tests, all 1,359 frontend tests, the frontend build and locale check. A live Discord desktop IPC handshake accepted the supplied application ID, activity and icon URL, and acknowledged a clear request. This is protocol evidence; it does not establish visual display or end-to-end detection of every Claude installation.

The user reported that the animated WebP appeared static in Discord. A six-frame GIF with the same timing was prepared and its published bytes and IPC acceptance were verified. Discord's image proxy returned HTTP 403 to an automated request; GIF playback in the actual client remains unverified, and changing formats is not proof that the original symptom is resolved.
